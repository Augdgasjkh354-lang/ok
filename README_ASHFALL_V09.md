# 《卡拉迪亚：烽烟与暗流》v0.9「路上的旧人」

**状态：源码已编译、静态审计已通过；未进行 Windows《骑马与砍杀：战团》客户端实测。**

## 目标

保留现有卡拉迪亚战争和政治循环，让玩家过去的行为在之后的旅途中出现具体回响。回响发生在原版村庄访问菜单，尽量不添加额外的任务追踪、通知轰炸或新的空转数值。

## 新增三条故事

### 1. 那群流民后来怎么样了？

- 玩家在 v0.2 的真实地图流民队伍遭遇菜单中提供过 **150 第纳尔路费**。
- 流民必须在地图上真正抵达安全城镇；半途消散或被截停不算。
- 抵达后至少过 **7 天**，玩家再次访问故乡时可能遇到认识自己的赶车妇人。
- 玩家可选择 **收下两袋谷物**，或 **把粮食留给村庄**（战乱 -4、繁荣 +2）。
- 同村只会触发一次该类回礼，不能利用反复出钱刷粮食。

### 2. 旧日逃兵来投

- 玩家在 v0.2 的真实逃兵遭遇中成功招安六名士兵，原价 600 第纳尔、统御至少 2；交钱遣散不算。
- 至少过 **10 天**，返回逃兵故乡时，两名知道玩家曾经宽待逃兵的旧兵主动请缨。
- 玩家可把他们纳入军队（原文化兵种 2 人），或派他们 **留守村庄**（战乱 -10）。
- 队伍满员时不会失去接纳机会；每个故乡此类回响只结算一次。

### 3. 村长记得这两次援助

- 玩家在同一村庄累计完成 **两次实际结算** 的 v0.1 救济、巡防或运粮行动，不计只预约未结算的援助。
- 第二次完成后至少过 **14 天**，访问村庄可听到村长与当地人的答谢。
- 玩家可选择 **两袋谷物** 或 **两名自愿随军的哨兵**（`trp_watchman`）。
- 同一个村庄该类机会终身最多结算一次，避免变成每天收菜的任务。

### 可发现性

城镇打听传闻时，如果附近没有更紧急的战乱消息，而某个邻近村庄已准备答谢玩家，过路商人可能提到「村里有人在找你」。维持原本传闻的 3 日冷却，优先显示真正的地方战乱，不增加每日弹窗。

## 中文和编译修复

1. 原 `module_scripts.py` 文件头声明 `cp1254`，新源码统一改用 `utf-8`，使源文件里的中文能够正确被 Python 解析。
2. 旧编译遗留的三条 `quick_strings.txt` 乱码字符串，其 ID 和顺序全部保持不变，仅修复**显示内容**为「无有效线索」和「暂无」。
3. 新增 `generate_localization.py`，生成 Warband 的 `ID|翻译文本` CSV：`game_menus.csv`、`quick_strings.csv`、`troops.csv`、`party_templates.csv`。
4. 按用户样本给新增匪首和地图部队提供带汉字间空格的简体中文名称，不去重写玩家原有 `trp_*` 名字。
5. 同时交付 `cns` 和 `cn_s` 目录供匹配实际游戏配置。没有额外扩展需求。
6. 本地化文件为**增量资源**。已安装中文补丁的用户不要直接用增量 CSV 覆盖完整汉化文件，使用 `merge_localization.py` 合并。脚本会给原有 CSV 留 `.bak` 备份，并且不会替换原版译名。

## 编译与安装

源码版执行：

```bash
python build_v09.py
python generate_localization.py
python tests/verify_v09.py
```

- **累计安装包**：已装 FewerBandits v7.5 的模块，复制 `FewerBandits/` 下 `.txt` 文件到现有模块根目录。
- **增量安装包**：已装《烽烟与暗流》v0.8 的模块，复制同名 `.txt` 文件覆盖。
- **从 v7.4 升级**：使用「从v7.4累计包」，已包含 v7.5，无需另装 v7.5 增量包。
- **汉化（只能合并）**：游戏每种语言只认固定文件名（如 `troops.csv`），Mod 译文只能写进玩家已有的同名文件，直接复制会覆盖原有完整汉化。因此安装包里的汉化放在 `汉化_需合并_不要直接复制/`，文件改名为 `*.merge.csv`（误复制也不会被游戏读取）。把 `Modules\\TestMod` 文件夹拖到其中的 `双击合并汉化.bat` 上即可合并，无需 Python；装了 Python 也可运行 `python merge_localization.py "C:\\...\\Modules\\TestMod"`。语言目录默认自动选择（已有 `cns` 用 `cns`，只有 `cn_s` 用 `cn_s`），首次合并前的原文件保存为 `*.csv.bak`，重复运行不覆盖备份；遇到非 UTF-8（如 GBK）文件会停止且不改动任何文件。输出保留官方文件开头的空行（游戏会跳过每个 CSV 的第一行）；**只合并进模组已有的 CSV，从不新建**：模组原本没有的文件（如只带 `troops.csv` 的 v7.4）若新建出只含本 Mod 条目的版本，会挡住游戏自带的完整中文，使开局等原版菜单变英文；用 Native 译文补底也不安全，因为 Mod 复用了原版 ID 却改了文字（如 `mno_continue` 改成「普通开局」，Native 译作「继续……」）。本 Mod 的菜单文字大多已直接编译进 `menus.txt`，跳过这些文件影响很小。
- **打包**：`python package_v09.py [输出目录]` 生成 v0.8 增量包、v7.5 累计包和 v7.4 累计包（默认输出到 `dist/`）；`python tests/test_merge_localization.py` 检查合并规则与包结构。
- 交付文件不是可独立运行的 Native Mod；须保留原模块的资源目录、`module.ini`、`map.txt` 等文件。

## v1.0 雇佣兵线（一）：饷银出自国王的钱袋

原版雇佣兵的周薪凭空生成，与雇主国库无关。现改为：
- 每周发饷时，饷银从雇主国王的真实财产（`slot_troop_wealth`）里扣除；
- **拖欠**：国王财产不够付本周饷银，或者自上次发饷以来王国丢了城堡或城镇时，本周饷银记为欠款。财务表会显示「拖欠的饷银（累计）」，同时弹出提示；
- **补发**：国王付得起时，欠款一次补清。玩家没在难处时离开，国王关系 +2，并记下玩家忍过的周数（`slot_af11_merc_endured`，留给以后的"以地代饷"）；
- 营地「清点拖欠的饷银」（只在有欠款时出现）：
  - 派人催讨：7 天冷却。国王付得起就付清，国王关系 −1；付不起则国王关系 −2；
  - 撕约离开：放弃欠款，国王关系 −5。连续欠饷满 2 周再走，算雇主违约在先，不扣荣誉；不满 2 周就走，荣誉 −2；
  - 再等等。
- 换了雇主或已成为封臣时，旧欠款不再计算。
- 存档字段：`p_main_party` 的 Slot 860～865；不新增全局变量。原版财务表只改了雇佣兵发饷那一段（`budget_report` 的载入操作从 548 条增至 571 条）。`build_v09.py` 现在也会编译 `presentations.txt`。

**以地代饷**：国王还不起欠饷时，「清点拖欠的饷银」会多出一个提议：用国王**自己名下最穷的村庄**抵账（没有的话，用王国里尚未分封的村庄），条件是宣誓效忠、成为封臣。出现条件：
- 仍是该国雇佣兵，与国王关系 ≥ 0，国王的财产不足以还清欠款；
- 当前已连续欠饷 3 周以上；或者以前已经忍过 3 周以上欠饷（`slot_af11_merc_endured`），这次只要欠 1 周就会出现。
接受后按原版宣誓流程处理：重新加入王国、授予村庄、记录效忠日志、`$player_has_homage`=1、获得旗帜，并清空欠款，国王关系 +3。若该村庄正在王国议程上，议程会被撤下。

**待实机验收**：财务表的显示和排版、拖欠的触发频率、撕约后的阵营状态、以地代饷后的封臣状态（旗帜、议事、封地收入）。

## v1.0 威名：战绩越吓人，敌人越不敢追

玩家要求：常胜、以弱胜强、亲手击倒的人多，敌人就越不敢主动来打；战绩离谱时，哪怕玩家只带几个人也不一定有人敢上。**只做"不追"**：敌人不会因此逃跑，玩家主动去打，他们照样迎战。

**威名怎么算**＝战功（`p_main_party` Slot 875）＋玩家本人一生杀死和打晕的人数 ÷ 10（引擎自带的统计，实时读取，不另存）。
- 打赢一场：战功 +1；以弱胜强另加：开战时敌方强度是我方的 1.5 倍 +2、2 倍 +4、3 倍以上 +8。敌人强度不到我方三分之一，或者玩家出力不到四成的仗，不计。
- 打输一场（全军覆没被俘）：战功 −20%。
- 两周没打过仗：战功 −1 点，之后每两周再 −1 点，最低 0（Slot 876 记下次的日子，每次打仗重新计时）。
- 分档：30 小有名气，80 威震一方，150 传奇，300 无敌，600 神话。升降档时会有一句提示。

**敌人怎么判断**（每小时检查一次，威名不到 30 时不检查）：玩家 6 个地图单位内的敌对部队，每支 12 小时内只判断一次（Slot 877 记在该部队上）：
- 不敢追的几率＝威名 − 底气 × 兵力比，最高 90%（4、5 档最高 95%）。兵力比＝对方强度 ÷ 玩家部队强度，最多按 3 倍算；
- 底气：土匪和其他部队 20；领主 30＋声望 ÷ 20，好战的 +20，好色贪杯的 −10，元帅 +30；
- 不敢追：12 小时内不追玩家（原版 `party_ignore_player`）；对方本来占优势时会提示「远处的某某望见你的旗号，没有上前」；
- 不判断的部队：花钱买了平安的、正在围城的。

举例：威名 100，遇上兵力是你 2 倍的普通领主（声望 500，底气 55），几率＝100−110＝0，照样追你；遇上 1.5 倍兵力的匪帮（底气 20），几率＝100−30＝70%。威名 250 时，三倍兵力的普通领主也有 85% 的几率不追，好战的元帅（底气 105）则照追不误。

**树大招风：有人想拿你立威**（试玩包三之后新增）：
- 威名到 80 以后，和你交战的好战领主（20 个地图单位内；元帅不来，他会把整支大军带来）每天各掷一次，几率＝威名 ÷ 10%（最高 25%），一旦掷中就带兵来找你，同一时间最多一个。提示「某某放出话来要拿你立威，正带兵朝你这边来」。他会追你 3 天，每小时重新下令，免得原版 AI 把他叫走；3 天没打上就作罢，15 天内不再来。4 档时这个每日几率减半，5 档时没人敢来（已经在路上的那位照常追完 3 天）。
- 他打赢你：声望 + 威名 ÷ 5（最多 40），30 天内不再来。
- 你打赢他：如果是惨败（你方战后还剩开战时 75% 以上的战力，伤员不算），他从此再也不敢找上门；否则 30 天后可能再来。
- 累计打败三位找上门的领主后，再没人来找你；好战领主和元帅也失去额外的底气（+20、+30），和其他领主一样按威名判断追不追你。
- 存档字段：`p_main_party` Slot 878（打败了几位），领主 Troop Slot 879～880（状态、日期）。**待实机验收**：领主是否真的按命令追你、出现频率。

**查看**：营地菜单「听听人们怎么说你」显示威名、所在档位、战功、亲手击倒人数，以及再过几天不打仗会减少 1 点战功（试玩包三之后新增，只读页面，追加一个菜单）。

读旧档时，已经杀过很多人的老角色一进游戏就有相应的威名（击倒 1000 人＝100 点）。新增 7 个脚本、1 个每小时触发器，不新增全局变量，不改对话。**待实机验收**：引擎是否严格按 `party_ignore_player` 停止追击（尤其是领主）、提示频率、数值手感。

- **待实机验收**：领主部队被设为追打匪帮后，原生阵营 AI（元帅命令、随军、围城）会不会很快把它拉回去；猎杀提示的时机；领主财产分布（L2 的 500／L4 的 300／L7 的 800 是否在领主付得起的量级，若多数领主长期 <500，L2 几乎不触发，需下调金额）；L5 报复的目标村选取（村庄的领主 Slot 是否可靠）；L6 领主无部队时 6 人散去有没有报错；L8 通风报信的 2 天窗口够不够（设计上一次猎杀只能用一次，实际是 2 天窗口内可报 1–2 次，信任 +5／次，猎杀本身稀有，刷不动）。

## v1.0 经济（十）：商人转卖

原版每周刷新时给城镇商人凭空补钱（杂货商身上少于 1500 就加 500～999，防具／武器商少于 1000 加 250～499，马商少于 600 加 250～499）。现在改成转卖：

- 每个商人有一笔**周转金**：杂货商 2000，防具商、武器商 1250，马商 800。
- **你卖给他货**，他的钱就少了。这批货他转卖给城里人，每周刷新时用**城里人的购买力**把他补回周转金。购买力＝繁荣 × 15 ＋ 500（和城镇金库每周按繁荣进账是同一种"本地生产"），杂货商能用其中 40%，防具、武器、马商各 20%。
- 购买力是**每周的流量**，不是钱池：用不完不留，用完了下周照样有，不会永久枯竭；只有繁荣度掉了（打仗、被围、饥荒、流民跑掉），城里人才真的买得少。
- **你从他那买东西**，他的钱多出周转金的部分是进新货的钱，刷新时**交回城镇金库**。
- 原版的随机补钱删掉了。新开局商人身上是 0，第一周用购买力补起来。

**结果**：繁荣 100 的城每周购买力约 2000（杂货商能回 800，其余各 400），和原版一城四个商人每周补的钱相当；富城收得多，穷城、被打烂的城收不动。你一次卖太多，商人要几周才缓过来。

为什么不从金库出：调查（`docs/调查_驻军工资.md`）发现驻军工资和每天招兵会把大多数城的金库压在几百到一千多，按"最多拿四分之一"每周只能补给每个商人 100～220，普通城镇卖不动战利品。最早的版本按"旧货价值 − 新货价值"结算，但新货是随机生成的，会让商人大约一半的周被扣到 0，也弃用了（`af24_stock_value` 保留在脚本表里但不再调用）。

实现：`af24_settle_stock`（追加在末尾）；四个城镇商人的刷新脚本删掉原版随机补钱，改调这个脚本。村长不动，它本来就不补钱。**待实机验收**：卖战利品后下周商人的钱是否回升；新开局第一周商人有没有钱；旧存档读进来商人的钱是否正常（原来超过周转金的部分会在第一次刷新时交回金库）。

## v1.0 经济（八）：商队的钱箱

以前商队身上没有钱：被劫只能拿到货，玩家收的过路费也是凭空生出来的。现在每支商队都有一只钱箱（商队 Party Slot 873）：
- **钱从哪来**：商队出发时，从出发城镇的金库拿本钱，补到 600；以后每到一座城做买卖，再从那座城的金库补到 600。每次最多拿金库的四分之一，穷城拿不出就少带。
- **过路费**：玩家向商队收过路费，商队给的钱不超过钱箱里的数目，付出的钱从钱箱扣除。旧存档里的商队第一次被收过路费时，先从故乡城镇补上本钱。
- **被劫**：
  - 玩家打赢：钱箱归玩家。有盟友参战时按出力分，其余归盟友领主；玩家效忠 NPC 王国时，按威名档位上缴国王（和战利品一样，威名四）；
  - AI 领主打赢：进领主财产，三分之一归他的国王；
  - 三大匪帮打赢：进匪帮钱袋，匪帮会拿去招人；
  - 普通土匪打赢：被瓜分花掉，不再记账。
- **解散**：王国丢光城镇、商队被原版撤掉时，钱箱退回故乡城镇的金库。

**后果**：商路越乱，城镇金库补给商队花的钱越多，而城镇金库也是原版补充驻军的钱，驻军就补得慢。没到站的商队不会参与那座城的原版货价调整，所以货价不会回落，这部分是原版机制，没有另加涨价。

全图最多约 30 支商队（每国最多 5 支），所以读旧档后各城一次性付出的本钱合计约 1.8 万，摊到各城大约每城 1000，相当于城镇半周的收入。**待实机验收**：劫商队拿到的钱是否合适，各城金库会不会被商队拖得太空。

## v1.0 经济（七）：粮食

城镇粮仓不再只在围城时才有用：
- 粮仓越空，当地粮价越高（最多贵约五成），在交易界面就能看出哪里缺粮；
- 城镇菜单新增「把带来的粮食卖给官仓」（粮仓 < 80%、未被围城时出现）：按当地市价收购，钱从城镇金库出，每袋补充全城一天的口粮；
- 不在围城中、粮仓却低于 25% 时，每周繁荣 −1（饥荒）。
新增一个每周触发器（追加在末尾）；不新增 Slot 和全局变量。详见 `经济系统梳理.md`「三之四、粮食」。**待实机验收**：围城之后城镇多久能缓过来，粮价变化是否明显。

## v1.0 经济（六）：人跟着战乱走

流民队伍出发时，故乡村庄繁荣 −1；抵达城镇时，城镇繁荣 +1（原有）。人真正从乡下流进城里，半路散了就是真的没了。一次劫掠最多让村子流走 3 批人。旧存档里更新前就已上路的流民，到达时仍会让城镇 +1，这是一次性的小偏差。原则见 `经济系统梳理.md`「三之三、人口」。

## v1.0 经济（五）：战利品与国王的抽成

钱随战争流动：攻下城池会拿走金库，打败领主会缴获他的随军财物，劫掠村庄会拿走村里的现钱，击溃匪帮会拿到他们的钱箱；缴获的钱要上缴国王一部分——玩家按威名档位抽成（0 档 33%、1 档 30%、2 档 25%、3 档 20%，再减谈判换来的减免，最低 10%，威名四），AI 领主仍是三分之一。详细表格见 `经济系统梳理.md`「三之二、战利品」。挂钩位置：
- 原版 `game_event_simulate_battle`：AI 攻城成功后调用 `af16_sack_center`；AI 俘虏领主后调用 `af16_lord_war_chest`；
- 原版村庄劫掠完成时，再加上 `af16_take_village_cash`；
- 玩家：攻城胜利（`castle_taken` 分支）、击败领主（独自作战或出力 ≥ 40%）、劫掠完成菜单、`af04_player_victory`。

同时修正了救济的反馈：选项文字改为「繁荣+1、钱进村里钱袋」；援助第二天送到时，会显示繁荣、战乱、关系前后的数值。关系已到 30 时，会提示日常援助不再提升关系。这是 v0.8 的平衡规则，此前没有任何提示，容易被当成没生效。

## v1.0 经济（二）：军粮合同由谁付钱
