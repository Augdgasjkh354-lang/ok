# 《卡拉迪亚：烽烟与暗流》v0.8「守土之责」

**版本状态：Module System 源码完成、完整编译通过、静态兼容审计通过，尚未进行 Windows《战团》客户端实机测试。**

本版建立在 v0.7 完整源码上，保留 FewerBandits v7.5 政治系统及 v0.1～v0.7 的全部既有功能。它是 Astra 设计报告「守土之责」的**收紧版**：先打通政治问责、领主治乱、地方风声和真实后勤，不启用高风险的自动剥夺封地。

## 新玩法与现有系统的连接

1. **辖区战乱度**：每 3 游戏日，将城镇／城堡附属村庄的 v0.1 战乱值汇总，并加入活跃匪帮和 v0.6 战后未恢复程度。这个值只反映地理辖区状况；封地所有权仍由原版 `slot_town_lord` 决定。
2. **领主失职与国王问责**：按领主自己实际持有的城镇、城堡及村庄计算最高危机程度。战乱达到阈值会累积失职；失职达到 60 后，王国每 15 天最多发生一次问责，领主原版争议度 +6、与国王关系 -4。随军／围城的领主增长速度减半。自立的国王不会自我问责。
3. **治理贤名**：长期管辖安宁领地会获得缓慢增长的贤名（0～100），已接入原 FewerBandits 秘密派系的封地候选人评分，每 5 点贤名兑换 1 点微弱优势。
4. **AI 巡防治乱**：在原版 `npc_decision_checklist_party_ai` 低优先级行动阶段，兵力足够的空闲领主会优先巡逻自己战乱度达到 55 的辖区，不强行打断元帅、围城或已有作战行动。真实巡逻部队接近自己的中心，每日可降低自己真正拥有的附属村庄战乱度 2，并降低失职 1。连续巡防最多约 6 天，之后 10 天以上冷却。
5. **地方风声**：营地入口集中为「烽烟案头」，可查自身失职、贤名、领地乱度及已经听说的近期事件。进入城镇可询问附近传闻，最多每 3 天刷新一次；仅反映附近可观察到的地方动荡，不透露秘密资助者身份。旧情报菜单全部保留、可以从案头进入。
6. **真实军粮**：军粮运输队优先选择附近缺粮且未被围城的友方城堡，其他情况仍可送往城镇。送达时增加原版 `slot_party_food_store`，补给量为 3 天消耗量乘以剩余护卫／初始护卫，且不超过原版粮仓容量。普通运输队不再凭空增加城市繁荣度；玩家护送合同成功的 +2 繁荣奖励保留。老存档在路上的军粮队，首次计算会补全原始护卫记录，防止异常倍增。
7. **旧系统平衡**：封地怨恨每 30 天 -4，秘密派系成员在少于 15 名部队时才尝试避难；同一个军事委托发布城镇签约后 5 天内不能重复签约；赈灾用粮从 2 袋调整为 6 袋、战后赈粮与守城运粮改为 4 袋；村庄关系达到 +30 后，普通援助不再无限提升关系。

## 特意不包含的事项

- 没有自动没收玩家或 AI 的封地；避免在未经实机验证时损害长期存档。
- 没有开启地方请愿的独立任务链、城池暴动、全面领主弹劾或新版元帅战略 AI。这些在未来版本中单独设计。
- 没有更改角色对白表 `conversation.txt`，自然传闻通过城镇菜单与营地案头实现。
- 没有增加新地图、场景、模型、兵种或部队模板。

## 工程变动

- 新增 8 个脚本：`af08_record_rumor`、`af08_refresh_jurisdictions`、`af08_score_lord`、`af08_governance_tick`、`af08_pick_patrol`、`af08_patrol_relief`、`af08_prepare_desk`、`af08_ask_town_rumor`。
- 新增 2 个游戏菜单：`af08_desk`、`af08_town_rumor`，保留旧菜单 ID。
- 新增 15 个专用 Slot（800～822，离散分配），没有新增全局变量。
- 新增 1 个 24 小时触发器（内部治理更新每 3 游戏日执行）。
- 仅有 `scripts.txt`、`menus.txt`、`quick_strings.txt`、`simple_triggers.txt`、`variable_uses.txt` 五个编译数据文件相对 v0.7 发生变化，其他 27 份保持一致。

## 构建和安装

在完整源码包顶层执行：

```bash
python build_v08.py
python tests/verify_v08.py
```

- **增量包**：先具有《烽烟与暗流》v0.7，再覆盖压缩包 `FewerBandits/` 中的 5 个 `.txt` 文件。
- **累计安装包**：从已有 FewerBandits v7.5 基础一次性安装 v0.1～v0.8 的累计游戏数据。不是独立原版 Mod；仍需要原来资源文件及原版 mod 模块配置。
- **完整源码包**：保留历史基线、完整 Module System 和测试脚本，可继续修改或重编译。

以后集中实机验收时，优先检查旧存档载入、AI 巡防是否短时间覆盖原版元帅行动、城堡粮仓入仓、城镇传闻菜单、问责周期和自动生成部队之间的联动。
