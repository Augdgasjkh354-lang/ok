# 《卡拉迪亚：烽烟与暗流》v0.3 — 战争承包商

**版本状态**：已完成源代码、Warband Module System 编译、差异审计与重复构建；未进行 Windows《战团》客户端实机测试。

## 基础版本

- 基于 **v0.2「流民与逃兵」**，继承 v0.1「战乱与村庄」和 FewerBandits v7.5 的政治系统。
- v0.3 的游戏增量包必须覆盖在已经安装 v0.2 的模组上，**不能直接覆盖纯原版或 v7.5**。
- 不需要立即安装或实测，后续可以合并版本集中测试。

## 新玩法

### 动态军粮队

- 交战王国每天各有 24% 概率尝试派出军粮队，同一王国同一时间最多一支（含受托运输队），**全地图总量上限 8 支**。
- 军粮队以真实世界地图队伍存在，带有商队车夫、商队护卫和守卫，显示王国阵营，从本阵营城镇出发前往另一座本阵营的未被围困城镇。
- 每次通常优先选择 15–119 地图距离单位的路线，接近 38 单位的目的地更优先。
- 普通军粮队在抵达目标后将当地繁荣度提高 1 点，随后从地图移除。护送合同中的军粮队成功抵达后繁荣度提高 2 点。
- 单支军粮队最多在地图上存在 16 游戏日；目的地改变阵营时将撤销。出发城镇记录最早 4 天后才可再次作为自动发车点。

### 护送合同

- 入口：进入与玩家关系非负、且其王国正在交战的城镇 →「战争承包商·军粮委托」。
- 条件：玩家队伍至少 15 人，委托城镇有同阵营有效运输路线，世界军粮队尚未达到总量上限；玩家没有尚未清算的旧合同。
- 接取后，在签约城镇立即生成真实军粮队，自动沿世界地图驶向目标城镇。
- 期限：12 游戏日。报酬 = **1200 + 路线距离×20 第纳尔**。
- 系统每隔 6 游戏小时检查一次玩家与运输队的距离：小于 11 单位则有效护送检查 +1，距离较远则 -1，数值限制在 0–8。
- 运输队抵达目标城镇时，护送检查至少为 2 且玩家距离目标城镇小于 12，即标记完成；否则视为任务失败。运输队被消灭、超时或原目的地易手也视为失败。
- 完成后返回原签约城镇领取报酬及 2 点声望；单次合同仅能领取一次。

### 截粮合同

- 入口同上，需签约王国与敌国处于实际战争状态，且附近敌国存在可供运输的两座城镇。
- 接取时生成一支**敌国阵营军粮队**，从敌国城镇前往敌国另一城镇。这是一个真实地图目标，可被寻找和野战攻击。
- 期限：12 游戏日。报酬 = **2000 + 路线距离×24 第纳尔**。
- **完成判定仅绑定玩家的原版战斗胜利菜单 `mnu_total_victory`**。目标被其他领主、盗匪或 AI 消灭，不会记为玩家完成。
- 取得胜利后，敌军目的地繁荣度 -2，合同标为待结算，返回签约城镇领取酬金及 2 点声望。
- 敌军成功运达、丢失目标、目标超时和任务逾期均为失败；进攻其他国家的运输队遵循游戏原有外交和敌对规则。

### 合同记录与恢复

- 营地新增「军事委托记录」，可查看接取城镇、委托阵营、运输路线、合同状态、报酬、剩余天数、护送检查、成功／失败累计。
- 城镇委托所可接新合同、领取成功报酬或者登记失败。
- 为防止任务卡死，营地的委托记录可以主动注销任何尚未清算的合同：该合同放弃全部报酬并计为失败，不会删除已经付出的真实世界地图收益或成本。
- 一次只允许一个未结算的合同；旧合同的奖励不会因为重复打开菜单而重新支付。

## 新数据与构建

- 追加 13 个脚本（`af03_`）、4 个菜单、1 个 Party Template `pt_af03_supply_convoy`、2 个触发器（每日和每 6 小时）。
- 追加 18 个新 Slot：`slot_af03_*`，取值 **690–707**；没有新增全局变量，没有新增独立民心、玩家声望以外的重复统计。
- `module_scripts.py` 只变动了旧 `game_event_party_encounter` 的运输队入口，其余旧脚本保持原样；`module_game_menus.py` 原有的 `town`、`camp`、`camp_cheat` 和 `total_victory` 加入入口或胜利结算钩子。
- 以 v0.2 编译数据作为基线，32 个输出 `.txt` 文件中只有 6 个发生改变：`menus.txt`、`party_templates.txt`、`quick_strings.txt`、`scripts.txt`、`simple_triggers.txt`、`variable_uses.txt`。
- 原脚本、菜单、部队模板 ID 和 `quick_strings` 的旧前缀顺序完全保留；`variables.txt`、`conversation.txt`、`strings.txt`、`quests.txt`、`troops.txt`、`factions.txt` 不变。旧存档能否正常运行仍需游戏客户端验证。

### 可重复构建

在源码包顶层执行：

```bash
python build_v03.py
python tests/verify_v03.py
```

脚本从内含的 `baseline/v02/compiled` 构建，不依赖磁盘上其他版本的文件。游戏数据在 `game-data/` 中。
