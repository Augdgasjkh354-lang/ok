# 《卡拉迪亚：烽烟与暗流》v0.7 — 系统整合与平衡

**状态：v0.7 源码已实现，Module System 编译及静态兼容性检查通过。尚未在 Windows《骑马与砍杀：战团》游戏客户端中测试。**

## 这次开发的目标

v0.1～v0.6 已经拥有村庄战乱、流民与逃兵、战争承包、特殊匪帮、宫廷阴谋和围城战后治理。v0.7 不新增大规模玩法；它减少历史版本间的逻辑漏洞，并让玩家可以在一个界面查看世界动态。

### 1. 流民目标地动态复核

旧版流民在生成当天选好目标城镇，之后即使该城被敌国占领或正被围城，仍可能到达并让城镇繁荣度 +1。

现在每天结算时，会检查目标是否仍是一个**未被围城、与流民故乡所属阵营非敌对**的城镇。如果目标失效，调用现有的安全城镇查找脚本重选，并修改地图部队的真实 AI 目的地。如果所有城市都不安全，队伍暂时停留、不会在敌城错误结算，并按原版 v0.2 的 20 天最长生命周期自然消失。安全目的地到达后，原版既定的故乡战乱 -4、目的地繁荣 +1 规则保持不变。

注意：这套规则沿用 v0.2 以**当前故乡所属阵营**判定安全的方式；战时故乡易主的历史归属追踪留作以后版本处理。

### 2. 战争人口和军粮队刷新节奏

| 自主事件 | 旧概率 | v0.7 概率 | 已有数量上限 |
|---|---:|---:|---:|
| 高战乱村庄生成流民，每日尝试 | 20% | 16% | 全地图 10 支 |
| 高战乱村庄生成逃兵，每日尝试 | 13% | 10% | 全地图 7 支 |
| 交战王国生成普通军粮队，每日尝试 | 24% | 18% | 全地图 8 支、同王国至多 1 支 |
| 空闲匪帮自主袭扰邻近军粮队，每日尝试 | 28% | 18% | 仅现有 3 支有名匪帮 |

仅调整了世界**自动事件**的概率；玩家主动签约、救济、招安、雇佣匪帮、围城行动的价格和收益保持 v0.6 原样。旧版专用数量限制、冷却和事件资格判定继续有效。

### 3. 普通军粮队经济反馈限制

原 v0.3 中，任何军粮队每次送达都会提高目的地原版繁荣度。v0.7 将**普通自动派发的军粮队**的繁荣增益限制在目的地原版繁荣度低于 70 的情形。玩家接取的**护送委托**继续按现有规则为目的地增加 +2 繁荣度，不因此降低玩家奖励。

这条规则只是避免世界模拟不断无条件推高富裕城市的繁荣；不改变原版繁荣度的上限、税收及其他经济公式。

### 4. 营地「卡拉迪亚战局总览」

营地新增一个非作弊入口，可查看：

- 全图平均战乱度、战乱 >=60 / >=80 的村庄数量、战乱最高村庄及数值；
- 现存流民队、逃兵队、军粮队、特殊有名匪帮数量；
- 正在战后恢复的城镇和城堡数量；
- 当前参与战争的原版王国数量，以及玩家军事委托状态。

概览仅在打开界面时现场统计，不在每帧运行，不新增存档 Slot 或独立民心。界面可以直接跳转到原有军事委托日志。

## 源码变更

- 新增脚本 2 个：`af07_retarget_refugees`、`af07_prepare_world`；新增菜单 `af07_world`。
- 修改原有脚本 3 个：`af02_daily_update`（目标安全和刷新率）、`af03_daily_update`（物流刷新率及繁荣限制）、`af04_daily_update`（匪帮自主行为率）。
- 修改原有 `camp` 菜单增加入口。
- **没有**增加 Trigger、全局变量、Slot、兵种、部队模板、场景或地图。
- 相比 v0.6，仅编译数据 `scripts.txt`、`menus.txt`、`quick_strings.txt`、`variable_uses.txt` 发生变化；剩余 28 个文件保持完全相同。
- 旧脚本及菜单 ID 在原有顺序保留，v7.5 宫廷政治数据、原版村庄关系、v0.1 战乱度与 v0.6 战后恢复原样继承。

## 构建与自动验证

源码包顶层执行：

```bash
python build_v07.py
python tests/verify_v07.py
python tests/simulate_v07_pacing.py
```

自动验证检查旧 ID 不变、源代码修改范围、32 份游戏数据的预期差异、旧对话/部队/持久化变量不变，并做 120 天**简化事件压力模型**（该模型验证概率/上限配置的边界，不模拟游戏 AI，也不能替代客户端实测）。完整构建所沿用的底层模块有原先三条可失败脚本警告，本轮未新增编译错误。
