## 一、目标与范围

玩家实测反馈的三个问题（2026-11-09）：①NPC 对白变化太少；②NPC 的判断没用上已有数据；③对白质量差、有"AI 味"。调查结论：v1.0 一句新 NPC 对白都没加，16 个新 Slot 在对话条件里出现 0 次；玩家抱怨的"对白"其实是 26 个菜单＋约 110 条提示消息。

**A 线（治"AI 味"）**：改写菜单正文、选项、提示消息的文字。只改文字与少数判断分支，不改任何数值、价格、概率、冷却与钱流。

**B 线（治"变化太少"）**：把已有数据接进对话条件，让 NPC 按"你是谁、你干过什么"换招呼。新增对话行约 12 行，全部追加在文件末尾。

**两条线一个工作分支、一次合并。实施顺序：B-0（工具前提）→ A 线 → B 线，每条线完成跑四命令。**

### 改写原则（A 线验收标尺，5 条）

1. **选项只写动作和代价，不写效果。** 价格（第纳尔数）、人数、袋数是代价，保留；"战乱-3、关系+4、繁荣+1""40%或65%成功率""7天冷却"这类效果与概率，从选项里删掉，效果写进点完之后的结果消息里，或者干脆不写。参考值：选项超过 15 个字就太长（参考值，不是硬规矩；"勒令他们放下武器""装没听见""据理力争"这种 5～8 个字的是标杆）。
2. **数字先分档，再说话。** 关系、交情、荣誉、声望这些数，先在代码里分三档（低／中／高），每档一句不同的话，再把人名、地名、数量填进去。只换数字不换话，就是模板。af10 村长打听已经是这个写法，照着它改。
3. **每段文字先定"谁在说"。** 村长、军需官、匪帮头子、国王、书记，各有各的口音；写之前先写一句这个人会说的话。没有说话人的地方用叙事口吻（af09 回响、af12 判后消息那种），不用"当前／暂时／已生效／无法"这种系统日志口吻。删掉所有"本页面只读取……""只有王国封臣可以……"这种写给开发者的句子。
4. **短句为主，一句不超过 20 个字，一段不超过 3 句。** 删掉"目前、当前、已经、正在、需要、应当"和"（0无、1有……）"这种密码本。数字 0／1 直接翻译成"有／没有"；百分比和天数只在非说不可时说，而且要说成"还得等 4 天"而不是"冷却剩 4 天"。
5. **失败只说真正的原因，成功先说人话。** 代码每次只卡在一个条件上，就报那一个，别把三个可能的原因并列。成功消息先写发生了什么（"村里人收到了你的钱""鞭子落了十下"），数字放后面——或者不放。af12 的 9 条判后消息和 af09 的回响消息已经是这个写法，照着它们改。

## 三、B-0 工具前提（先做，其他都依赖它）

### B-0-1 对话追加：放宽两处行数断言，改成"追加制"

现状（已核对，基线 `24fe57d7`）：

- `build_v09.py` 的 `merge_dialogs` 有 `assert len(fresh)==len(old), 'dialogue count changed: append-only rule needs review'`——追加新对话行会直接构建失败。
- `tests/verify_v09.py` 第 72 行有 `assert len(_old)==len(_new), 'dialogue count changed'`——同样拦住追加。

改法：两处都改成追加制——旧对话 ID 必须按原顺序全部出现在新文件前部，新 ID 只能追加在末尾；旧行内容与顺序仍按现有规则校验（`merge_dialogs` 逐行比对逻辑不变，`ALLOWED_DIALOG_CHANGES` 仍管旧行逻辑改动）。断言信息里写明"append-only"。

验证：改完先跑四命令（此时一行对话未动，必须全过），再做 B-1 的第一行新对话，跑四命令确认新行能进 `game-data/conversation.txt` 且旧行一行未变。

### B-0-2 对话中文的改动路径：先用一行探路，再批量

现状（已核对）：`merge_dialogs` 逐行比对时，若新旧两行只有一个 token 不同、且旧 token 是非 ASCII（中文），则**保留旧行**——也就是说，只改源码里的中文文字，游戏里是看不到的；显示的中文要走本地化 CSV（`dlga_` 键）。

做法：先拿 A-14 村长捐钱那一行做探路——改完源码行与 CSV 条目后跑四命令，检查 `game-data/conversation.txt` 与 `localization/cns/dialogs.csv` 里该行的中文是否变成新文本。确认路径后，把确认后的步骤（动哪几个文件、先后顺序）写进本规格末尾"附：对话中文改动路径（B-0 探路结论）"，再批量做其余行。**探路结论没写进附录之前，不批量改对话中文。**

## 五、B 线：对话接数据（8 项，约 12 行新对话）

> 机制前提（已核对）：NPC 的话从上往下扫，第一条符合条件的胜出；新行只能追加在文件末尾。**所以每条新招呼句必须插在它要替代的通用句之前**——追加在文件末尾的新行，引擎扫到它时通用句还在前面等着，永远轮不到。正确做法：把旧通用行的条件收紧（逻辑改动，进白名单），让新行在旧行之前被扫到；或者把新行做成"起始状态 `start` 里排在通用句之前的新行"——追加的行在文件末尾，但同一状态内的行按文件顺序扫描，**追加的新行在文件里排在通用行之后，扫描时通用行先被试到**。这一点实施时必须先想清楚：可行的办法是收紧旧通用行的条件（例如村长招呼加"60 天内没被劫过"），让新行在旧行被排除后才被扫到；或者把新行放在通用句的**同一状态、但通过条件互斥**实现。**B-0 之后、动手之前，先用 B-3 这一行验证"新行确实能轮到"的办法，把验证结论写进附录，再批量做其余行。**

## 附：新行轮到机制（B-3 探路结论）

> B-3 探路结论，2026-11-09 实测（基线 2292d938）。探路行：B-3 村长认出劫掠者。

**办法：收紧旧通用行的条件（互斥），而不是指望新行排在前面。** 新行只能追加在文件末尾，同一状态里旧通用行先被扫到；只有旧行在新行要出现的条件下不匹配，新行才轮得到。B-3 的做法：4 句旧村长问候都加上 `(call_script, "script_af25_village_looted_recently", "$current_town"), (eq, reg0, 0)`；新行条件是同一脚本返回 `reg0 == 1`。两边互斥，旧行被排除后扫描才走到新行。

**辅助脚本** `af25_village_looted_recently`（追加在 `module_scripts.py` 末尾）：取村庄作参数，读 Slot 894，按与 `af09_check_echo`、志愿兵清零同一口径（当天+1 减去劫掠日，小于 60 天）返回 `reg0` 1/0。复用现有脚本不够（`af09_check_echo` 的 reg0 是回响种类，劫掠时与无回响同为 0，分辨不出来），所以新写一个 12 行的小脚本。

**工具链修正**：`conversation.txt` 前两行是文件头（`dialogsfile version 2`）与对话总数，不是对话 ID；B-0 的 `merge_dialogs` 与 `verify_v09.py` 对话校验都得跳过这两行（否则总数 2813→2814 会报 `dialogue order changed`）。已修 `build_v09.py` 与 `tests/verify_v09.py`，零内容改动时四命令仍全过。

**探路证据**：构建显示 `dialogue lines taken from source: 56`（51＋4 旧行条件＋1 总数）；四命令全过；新行在 `game-data/conversation.txt` 末尾，ID 由编译器自动编为 `dlga_start:village_elder_talk.4`，中文原文已进编译行；`localization/cns/dialogs.csv` 有该键的逐字加空格条目；4 句旧问候的编译行已带上新条件（以 `.3` 行为例，条件数 1→3）；旧行 4 个 ID 已进 `ALLOWED_DIALOG_CHANGES`。

**结论**：互斥条件法可行。其余 B 行照此办理——新行追加在末尾，凡是同一状态里已有通用行挡路的，都把通用行收紧（进白名单），新行条件与通用行的排除条件互斥。**实机点**：村长在被劫后 60 天内见到玩家，是否确实说新句（而不是旧句或无话可说），需实机验证。
