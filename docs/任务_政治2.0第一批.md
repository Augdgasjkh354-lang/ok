## 0. 场景

你自立为王，手下有几位封臣。王国在打仗。

某天，信使同时带来两份请愿：

- 哈伦领主：「仗打了三个月，我的人快发不出饷了。请陛下拨 2000 第纳尔军费。」
- 雷玛领主：「臣的封地{村名}被劫了两回，百姓快撑不下去了。请陛下拨 1500 第纳尔赈济。」

你身上只有 2500，只能准一份。你准了雷玛的赈济：村子拿到钱，雷玛记你的好；哈伦的请愿被驳回，而且你明摆着先顾了别人，他对你的不满更重一点。

**为什么这样做**：
- 原版宰相已经管了分封地、任命元帅（`minister_grant_fief` 等），本批不碰这些，只做「要钱」的请愿。
- 你当国王时，**王国的钱就是你身上的金币**。玩家没有 `slot_troop_wealth` 这一说，一律用 `troop_remove_gold`／`store_troop_gold`，不要读写玩家的 `slot_troop_wealth`。
- 两份请愿同时来、钱只够一份：GPT 提的「多位领主争有限的钱」就落在这里，不另做 NPC 国王的财政 AI。

**钱的流向**（经济规则 2）：
- 军费：玩家金币 → 封臣财产（`af14_lord_wealth`）。
- 赈济：玩家金币 → 村长钱袋（`af13_village_purse`）。
- 驳回：什么钱都不动。

## 2. 新脚本（`build/module_scripts.py`，追加在 `scripts` 列表末尾）

### 2.1 `af49_is_player_king`（只读）

- 无参数。输出 `reg0`：1 是，0 不是。
- 条件：`$players_kingdom` = `fac_player_supporters_faction`，并且 `fac_player_supporters_faction` 的 `slot_faction_leader` = `trp_player`（支持称王者时，国王是那位称王者，不是你，不算）。

### 2.2 `af49_find_petitions`（只读）

- 无参数。输出（**全部放到最后赋值**）：
  - `reg0` = 要军费的封臣（没有为 -1）；
  - `reg1` = 要赈济的封臣（没有为 -1）；
  - `reg2` = 赈济的村子（没有为 -1）。
- 前提：`af49_is_player_king` = 1。不是就三个都返回 -1。
- **封臣**的定义：`active_npcs_begin`～`active_npcs_end` 里，`store_faction_of_troop` = `fac_player_supporters_faction`、`slot_troop_occupation` = `slto_kingdom_hero`、没被俘（`slot_troop_prisoner_of_party` = -1）、不是玩家。
- **要军费的**（A）：王国正在打仗（照 `:faction_is_at_war` 的写法：`try_for_range` `kingdoms_begin`～`kingdoms_end`，`slot_faction_state` = `sfs_active`，`store_relation` < 0）；封臣财产 `slot_troop_wealth` < 1000；挑财产最少的那位。
- **要赈济的**（B）：在 `villages_begin`～`villages_end` 里找封主（`slot_town_lord`）是封臣的村子，满足繁荣 < 40 **或** 战乱 `slot_af01_unrest` ≥ 20（读之前先 `af01_ensure_village`），且不在被劫（`slot_village_state` ≠ `svs_being_raided`）；挑繁荣最低的村，封主就是 B。**B 不能和 A 是同一人**：如果最穷的村的封主就是 A，跳过这个村、找下一个。
- 玩家自己的村子（`slot_town_lord` = `trp_player`）不算，那是你自己的事。

### 2.3 `af49_grant`（写状态，批准一份请愿）

- 参数 1：种类（1 军费，2 赈济）；参数 2：封臣；参数 3：村子（种类 1 时传 -1）。
- 输出 `reg0`：1 办成，0 钱不够没办。**先查钱，钱不够什么都不动**。
- 军费：金额 2000。玩家金币 ≥ 2000 → `troop_remove_gold` 玩家 2000；`af14_lord_wealth`（封臣, 2000, 0）；玩家↔封臣关系 +4；`slot_fb71_fief_grievance` −5（最低 0）。
- 赈济：金额 1500。玩家金币 ≥ 1500 → `troop_remove_gold` 玩家 1500；`af13_village_purse`（村, 1500）；`af01_change_unrest`（村, −5）；`change_center_prosperity`（村, 2）；村庄关系 < 30 时 `change_player_relation_with_center`（村, 2）；玩家↔封臣关系 +3；`af01_record_event`（村, 5）。

### 2.4 `af49_refuse`（写状态，驳回一份请愿）

- 参数 1：封臣；参数 2：另一份是否被批准了（1／0）。
- 玩家↔封臣关系 −2；参数 2 = 1 时再 −1（「你先顾了别人」）。
- 不动钱。

## 3. 每周触发器（`build/module_simple_triggers.py`，**追加在末尾**）

照资本家 2.0 信使借钱那个触发器（`slot_af33_loan_visit_day` 那段）的写法：

```
(24*7, [
  (store_current_day, ":today"),
  (party_get_slot, ":next", "p_main_party", slot_af49_petition_day),
  (ge, ":today", ":next"),
  # 别和信使借钱同一周撞车: 借钱信使 3 天内来过就这周不来
  (party_get_slot, ":loan", "p_main_party", slot_af33_loan_visit_day),
  (store_sub, ":since_loan", ":today", ":loan"),
  (this_or_next|eq, ":loan", 0),
  (ge, ":since_loan", 3),
  (call_script, "script_af49_find_petitions"),
  (this_or_next|ge, reg0, 0),
  (ge, reg1, 0),
  (store_add, ":next", ":today", 14),
  (party_set_slot, "p_main_party", slot_af49_petition_day, ":next"),
  (jump_to_menu, "mnu_af49_petitions"),
]),
```

冷却在信使来的时候就记下（玩家怎么处理都算用掉这一次）。顶层这些条件不满足时整个触发器本来就该跳过，所以这里不用包 `try_begin`。

## 4. 新菜单 `af49_petitions`（`build/module_game_menus.py`，追加在 `game_menus` 末尾）

- 标志 `mnf_scale_picture`，背景 `mesh_pic_messenger`（照 `af33_loan_call`）。
- 进菜单时调 `af49_find_petitions`，拼正文进 `s40`：
  - 只有 A：「信使带来{A}的请愿：仗打得久了，手下快发不出饷，请陛下拨 2000 第纳尔军费。」
  - 只有 B：「信使带来{B}的请愿：封地{村}的百姓快撑不下去了，请陛下拨 1500 第纳尔赈济。」
  - A、B 都有：两句都写，中间 `^`，开头加一句「两位封臣同一天递来了请愿。」
  - 末尾一行：「你身上有 {reg41} 第纳尔。」
- 选项（每个选项的条件和后果里都**重新**调 `af49_find_petitions` 取 A、B、村，照 `af33_loan_call` 的做法；不要用全局变量存）：
  1. 「准{A}的军费（2000）。」条件：A ≥ 0、金币 ≥ 2000。后果：`af49_grant`（1, A, -1）；B ≥ 0 时 `af49_refuse`（B, 1）。离开菜单。
  2. 「准{B}的赈济（1500）。」条件：B ≥ 0、金币 ≥ 1500。后果：`af49_grant`（2, B, 村）；A ≥ 0 时 `af49_refuse`（A, 1）。离开菜单。
  3. 「两份都准（3500）。」条件：A ≥ 0、B ≥ 0、金币 ≥ 3500。后果：两份都 `af49_grant`。离开菜单。
  4. 「都驳回。」无条件。后果：A ≥ 0 时 `af49_refuse`（A, 0）；B ≥ 0 时 `af49_refuse`（B, 0）。离开菜单。
- 选项文字里的名字：在选项**条件**里 `str_store_troop_name` 进 `s11`（A）、`s12`（B），文字用 `{s11}`／`{s12}`。
- 离开菜单照 `af33_loan_call` 的写法（`change_screen_return` 或它用的那个）。
- 每个后果末尾 `display_message` 一句结果，例如「{A}收到了军费。」「{村}收到了赈济，{B}会记得这份情。」「{A}的请愿被驳回了。」——中性称呼，不用「他」。
