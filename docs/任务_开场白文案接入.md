## 0. 目标和接法

**目标**：NPC 开口第一句话提到玩家和他之间的事（欠钱、入股、交情、名声等）。不加任何玩家选项。

**文案**：已筛好，放在 `build/af39_remarks/`，三份文件，每行 `场景键|性格键|台词`：
- `lords.txt`：285 句（领主／国王）
- `gangs.txt`：173 句（六帮头目）
- `town.txt`：56 句（酒馆老板 tavern／镇长 mayor／村长 elder）

台词一个字也不要改。要改文案的话改这几个 txt，然后重新构建。

**为什么这样接（重要）**：之前的教训是，追加在对话文件末尾的 `start` 行排在原版兜底句后面，根本轮不到（酒馆老板因此喊过“投降还是死”）。所以本任务不靠“多加几行对话碰运气”，而是：
1. 在每次对话开始时都会运行的“存变量”那一行（`dlga_start:close_window`，`build/module_dialogs.py` 约第 146～150 行）里，调用脚本决定这次要不要说一句开场白；要说，就把整句写进 `s42`，并用原版已有的全局变量 `$g_comment_found` 做标记。
2. **领主**：原版本来就有“领主开场评论”机制：`$g_comment_found` > 0 时，`lord_start` 状态里的 `{s42}` 行（约第 6098 行）会把 `s42` 说出来。我们只是在原版没找到评论时填一句自己的，原版那行**不用改**。
3. **酒馆老板、镇长、村长**：给原版问候加一个“没有开场白时才说”的条件，再在文件末尾追加一行“有开场白时说 `{s42}`”。兜底的“Surrender or die”／“Hello”两行已经跳过酒馆老板和村长，这次再加上镇长，追加的行就能轮到。
4. **匪帮头目**：头目说的话本来就是菜单正文里的 `s13`（`script_af04_prepare_gang` 设置）。在这个脚本末尾调用新脚本，按条件改写 `s13`。

`$g_comment_found` 的约定：原版只给领主用，0＝没有，>0＝有评论。我们用 **1** 表示领主开场白，用 **2** 表示酒馆老板、镇长、村长的开场白。每次对话开始时原版都会把它清零（第 128 行），不会串到下一次对话。

## 1. 读文案的数据模块：新文件 `build/module_af39_remarks.py`

`module_scripts.py` 可以 import 同目录下的 py 文件。新建这个文件，在构建时读 txt、生成操作列表，避免手抄 500 多句。

要求：
- 用 `io.open(path, encoding='utf-8')` 读文件，路径相对本文件所在目录：`os.path.join(os.path.dirname(os.path.abspath(__file__)), 'af39_remarks', name)`。
- 跳过空行；每行用 `split('|', 2)` 拆成三段；同一个（场景，键）下的台词按文件里的顺序收集。
- 提供一个函数，生成“按编号选一句写进某个 s 寄存器”的操作列表：

```python
def pick_ops(filename, scenes, keys, scene_var, key_var, idx_var, sreg, wrap=None):
    """scenes / keys 是本规格第 2 节给出的有序列表，编号从 1 开始（0 表示没有）。
    生成：try_begin
            (eq, scene_var, si), (eq, key_var, ki),
            (store_mod, ":af39_i", idx_var, 该组台词数),
            try_begin (eq, ":af39_i", 0), (str_store_string, sreg, "@台词0"),
            else_try  (eq, ":af39_i", 1), (str_store_string, sreg, "@台词1") ... try_end
          else_try ...（下一组）... try_end
       wrap: 匪帮用，给台词加前缀，例如 lambda key, text: 头目名 + "说：'" + text + "'"。
    某个（场景，键）组合在文件里没有台词就跳过，不生成分支。
    文件里出现了 scenes／keys 之外的键，直接 raise，构建失败（防止拼写错误悄悄丢句子）。"""
```
- 操作用 `module_scripts.py` 已有的写法（`try_begin`、`else_try`、`try_end`、`eq`、`store_mod`、`str_store_string` 从 `header_operations` 导入）。
- `idx_var` 由调用方传进来，是一个已经算好的非负整数局部变量。

在 `module_scripts.py` 文件头的 import 区加一行 `from module_af39_remarks import pick_ops`。

### 2.1 `af39_lord_remark`（参数 1：领主 troop）

输出：`reg0` = 1 表示有开场白，整句在 `s42`；否则 `reg0` = 0、`s42` 不动。

**前提**（任一不满足就输出 0）：
- `slot_troop_occupation` = `slto_kingdom_hero`；
- 没被俘：`slot_troop_prisoner_of_party` = -1；
- `$talk_context` ≤ `tc_siege_commander`；
- `$g_talk_troop_faction_relation` ≥ 0（与玩家不敌对；这个变量在存变量那行里已经算好）；
- 五成机会：`store_random_in_range` 0～99，< 50 才继续（否则老说同一件事会烦）。

**性格键**（`slot_lord_reputation_type`）编号，用于 `pick_ops` 的 keys：
`keys = ['martial','quarrelsome','selfrighteous','cunning','debauched','goodnatured','upstanding']`，编号 1～7，正好等于 `lrep_martial`(1)～`lrep_upstanding`(7)。其他值的映射：`lrep_roguish`(8) → 5（debauched），`lrep_benefactor`(9) → 6（goodnatured），`lrep_custodian`(10) → 4（cunning），其余（包括 0 和女性性格 20 以上）→ 7（upstanding）。
