## 0. 为什么只做这三件

GPT 的政治 1.0 方案里，下面几项**其实已经有了**，不重做：

| GPT 方案里的 | 现有实现 |
| --- | --- |
| 领主主动争权、私下拉票 | v7.2 派系集体推举 `fb72_choose_caucus_nominee`；v7.3 AI 互相游说 `fb73_daily_intrigue` |
| 封赏后失意者记恨 | v7.2 `fb72_note_fief_contest`：落选者对国王 −2、对获封者 −3，派系怨气上升 |
| 玩家买票、互惠换票、毁约 | v7.3 `fb73_player_bribe`／`fb73_player_reciprocity`／`fb73_player_break_oath`；v1.0 L7 好感 50 白拿一票 `af26_free_vote`；元帅买票 `af33_bribe_marshal_vote` |

| 叛臣 | v7.4 派系倒戈（只在本国派系之间，不叛国） |

真正缺的是三样：
1. **看不见**：玩家不知道现在在议什么、谁领先、谁还没表态，只能挨个去问。
2. **只能替自己拉票**：买票、白拿票的候选人都写死是玩家。想帮朋友争封地，没有办法。
3. **失意者没人理**：`fb72_note_fief_contest` 给落选者记了 `slot_fb72_last_disappointment`（619），但**全仓库没有任何地方读它**。

## 1. 场景

你是斯瓦迪亚封臣。刚打下来的城堡上了议程。

- 营地 → 烽烟案头 → 宫廷政治情报簿 → **眼下的议题**：看到「议题：分封某城堡，已议 3 天。哈伦领主 4 票，克拉格斯领主 3 票，还有 6 位没表态。陛下倾向：克拉格斯领主。你投给：哈伦领主。」
- 你跟哈伦交情好，已经表态支持他。你去找还没表态的雷玛领主，说「这次评议，请你支持哈伦领主」。雷玛跟你、跟哈伦关系都还行，答应了。
- 封地最后给了哈伦：哈伦对你 +3，并且**欠你一张将来的封地票**（v7.3 现成的人情债）。克拉格斯落选——他已经由 v7.2 记恨了国王和哈伦；你替对手拉了票，他对你再 −2。
- 过两天你遇到克拉格斯，他还在气头上：「这城是我们一起打下来的，陛下却只记得他的人。」你可以答应下次评议站他那边（你欠他一票，v7.3 现成的结算会在下次封地议事时核对你守没守约），或者掏 1500 第纳尔帮他撑过这阵子。

## 2. 眼下的议题（只读菜单）

### 2.1 新脚本 `af46_agenda_text`（无参数，结果拼进 `s40`）

追加在 `scripts` 列表末尾。只在打开菜单时跑一次，不放触发器。

- 读本国 `slot_faction_political_issue`：
  - 0（或 < 0）：「眼下宫廷没有在议的事。」
  - 1：「议题：推选元帅。」
  - 在 `centers_begin`～`centers_end`：「议题：分封{据点名}。」
- 已议天数：（`store_current_hours` − `slot_faction_political_issue_time`）÷ 24。
- 得票：对本国每位领主（`active_npcs_begin`～`active_npcs_end`，`store_faction_of_troop` = 本国，`slot_troop_occupation` = `slto_kingdom_hero`）加玩家，读 `slot_troop_stance_on_faction_issue`：
  - -1 记「未表态」人数；
  - 其他值是候选人。统计得票**最多的前 3 位**（做法：外层循环候选人 c，内层数投 c 的人；O(n²) 只在开菜单时跑一次，可以接受）。玩家作为候选人时显示「你」。
- 国王倾向：国王（`slot_faction_leader`）的 stance。-1 写「陛下还没表态」；否则写名字。原版规则：国王与得票最多者关系 ≥ 10、或国王就投了他、或国王没表态，就按票数；否则国王说了算——这句规则写进菜单正文末尾一行，让玩家知道国王能推翻票数。
- 你投给：玩家自己的 stance（-1 写「你还没表态」）。
- 你欠／别人欠你的票：照 `fb75_book_overview` 的算法，各一行；为 0 不显示。
- 输出寄存器放到最后：`s40` 最后一次赋值之前不要再调用会改 `s` 寄存器的原版脚本（`str_store_troop_name` 可以，要用中间 `s` 寄存器拼接，最后 `str_store_string, s40, "@..."`）。

## 3. 替人说项（对话）

### 3.1 入口

在 `fb73_private_options`（「私下谈政治交易」里的选项状态）**文件末尾追加**两个玩家选项。共同条件：

1. 对方与玩家同国（`store_faction_of_troop` = `$players_kingdom`），`$player_has_homage` = 1；
2. 当前议题是封地（`is_between` `centers_begin`～`centers_end`）。**元帅议题不做**：原版注释写明承诺不影响元帅选举，结算也只跑封地议题；
3. 玩家自己已表态，且投的是一位 NPC 领主 X：`slot_troop_stance_on_faction_issue`（玩家）在 `active_npcs_begin`～`active_npcs_end`，X 与本国同阵营，X ≠ 对方；
4. 对方还没表态（stance = -1）、没有挂着的承诺（`slot_fb73_promise_candidate` = 0）；
5. 5 天游说冷却：照 `fb73_player_bribe` 用 `slot_fb73_last_lobby_day`（`last` = 0 或已过 ≥ 5 天）。

选项条件里把 X 的名字存进 `s11`。

- 选项 A「这次评议，请你支持{s11}。」——空口说情，不花钱。
- 选项 B「这次评议，请你支持{s11}。这{reg40}第纳尔算我一点心意。」——价钱 = `fb73_vote_price`（对方）；**条件里要求玩家金币 ≥ 价钱**。

### 3.2 新脚本 `af46_broker_vote`（参数 1：对方领主；参数 2：0＝说情，1＝出钱）

输出 `reg0`：1 答应，0 拒绝。输出寄存器放最后。

- 重新核对 3.1 的全部条件（对话条件和后果之间可能隔了一帧，照 `fb73_player_bribe` 的写法在脚本里再查一遍）。
- 成功率：
  - 关系 A = 对方对玩家，B = 对方对 X（都用 `script_troop_get_relation_with_troop`）；信用 = `fb73_get_credit`（玩家）。
  - 说情：`chance = 10 + A/2 + B/2 + (信用 − 50)/2`，钳在 5～80。
  - 出钱：`chance = 40 + A/2 + B/2 + (信用 − 50)/2`，钳在 5～90。
  - B < -10 时直接拒绝（他跟 X 有仇，给钱也不干）。
- **不管成败**都写 `slot_fb73_last_lobby_day` = 今天（防连刷）。
- 成功：
  - 出钱时：先查钱够（不够就当拒绝、不扣钱），`troop_remove_gold` 玩家，`af14_lord_wealth`（对方, 价钱, 0）进他的财产，`slot_fb73_paid` = 价钱（失约退款用）。
  - `fb73_record_promise`（对方, X, 议题, `trp_player`, **4**）——承诺类型 4 = 玩家替人说项，新值，`module_constants.py` 里 `slot_fb73_promise_type` 那行注释补上「4=玩家替人说项」。
  - 对方 stance = X。
  - 嫌疑：`fb74_add_heat` 对方 +8、玩家 +6（照互惠换票的量级）。
- 失败：只给对方 +3 嫌疑、不扣钱。

### 3.3 回应（文件末尾追加，状态 `af46_broker_result`）

`{s11}` 在后果里调过脚本后可能被改写，进回应前在后果末尾重新 `str_store_troop_name, s11, X`。

### 3.5 封赏结算：新脚本 `af46_broker_settle`（参数：阵营、议题、获胜者）

**必须在 `fb73_settle_court` 之前调**——`fb73_settle_court` 会清掉承诺 Slot。

挂点：`build/module_scripts.py` 原版议题结算处，现在是：

```python
        (try_begin),
          (faction_get_slot, ":fb73_issue", ":faction_no", slot_faction_political_issue),
          (is_between, ":fb73_issue", centers_begin, centers_end),
          (gt, ":winning_candidate", -1),
          (call_script, "script_fb73_settle_court", ":faction_no", ":fb73_issue"),

```

在 `(gt, ":winning_candidate", -1),` 之后、`fb73_settle_court` 之前插一行 `(call_script, "script_af46_broker_settle", ":faction_no", ":fb73_issue", ":winning_candidate"),`。

脚本内容：
- 只在阵营 = `$players_kingdom` 时做事。
- 取议题时间 `slot_faction_political_issue_time`。扫本国领主：`slot_fb73_promise_type` = 4、`slot_fb73_promise_partner` = -2（玩家）、`slot_fb73_promise_issue` = 议题、`slot_fb73_promise_hour` = 议题时间、并且**实际投票**（stance）= 承诺的候选人——守约的才算。按候选人分两类计数：投给获胜者的 `:won`，投给别人的 `:lost`（记下其中一个候选人做 `:lost_for`）。
- `:won` ≥ 1 且获胜者是 NPC 领主（`active_npcs_begin`～`active_npcs_end`）：
  - 玩家↔获胜者关系 +2 + `:won`，最多 +5（`script_troop_change_relation_with_troop`，原版量级）；
  - 获胜者 `slot_fb73_debt_to` = 0 时，写 `-2`（欠玩家一张将来的封地票），`slot_fb73_debt_since_hour` = 议题时间（v7.3 的写法：同一议程不能兑现）；
  - 消息：「{获胜者}得了{据点}。他记得那几票是你替他拉来的。」——注意中性称呼，改成「{获胜者}得了{据点}，记得那几票是你替其拉来的。」之类，**不要用「他」**（领主可能是女性）。文案交给 Fable 或照现有风格写。
- `:won` = 0 且 `:lost` ≥ 1，且获胜者是 NPC 领主、不是国王：玩家↔获胜者关系 −2，消息「{获胜者}知道你替{对手}拉过票。」
- 不碰金钱，不碰 `slot_fb73_credit`（信用由 `fb73_settle_voter` 统一结算，避免重复）。

## 4. 安抚失意者（对话）

### 4.1 入口

在 `lord_talk_court`（第一层「聊聊宫廷里的事。」进去的状态）**文件末尾追加**一个玩家选项「你最近好像不太痛快。」，条件：

1. 对方同国、玩家是封臣，对方不是国王；
2. `slot_fb72_last_disappointment` > 0，且今天 − 它 ≤ 14；
3. 对方对玩家关系 ≥ 0（跟你有仇的不跟你诉苦）。

### 4.2 对方诉苦（状态 `af46_grieve`）

「{据点}是我们一起打下来的，陛下却只记得自己的人。」——需要据点名：`slot_fb72_desired_center` 里通常就是那块地（`fb72_note_fief_contest` 在他没别的心愿时写进去）。为 0 时用不带地名的版本：「这一回陛下的封赏，没有我的份。」

### 4.3 玩家的三个选项（`af46_grieve` 状态下）

- **「下次评议，我站在你这边。」**
  条件：玩家 `slot_fb73_debt_to` = 0（玩家一次只欠一个人）。
  后果：玩家 `slot_fb73_debt_to` = 对方（troop 号，> 0），`slot_fb73_debt_since_hour` = `store_current_hours`；关系 +3；对方 `slot_fb72_last_disappointment` = 0（一次失意只能安抚一次）。
  之后的结算全部是 v7.3 现成的：下一次本国封地议事结算时（`fb73_settle_voter` 对玩家跑一遍），玩家投了他 → 信用 +4、关系 +4；没投 → 信用 −12、关系 −8、失信次数 +1。玩家要投他，原版就有「我支持你」的对话（跟他本人说话表态）。
  对方回应：「这话我记下了。到时候可别装没看见。」
- **「我出 1500 第纳尔，帮你撑过这阵子。」**
  条件：玩家金币 ≥ 1500（先查钱）。
  后果：玩家 −1500，`af14_lord_wealth`（对方, 1500, 0）进他的财产（他拿这钱养兵）；关系 +2；`slot_fb71_fief_grievance` −10（最低 0）；对方 `slot_fb72_last_disappointment` = 0。
  对方回应：「……这份情我领了。」
- **「这是陛下的决定，我不便多说。」** 回到 `lord_talk_court`，什么都不改。

## 要玩家定的

1. 说情的成功率公式和出钱的价码（照买票价 3500～12000）合不合适。
2. 安抚失意者给 1500 第纳尔是不是太便宜／太贵。
3. 替对手拉票被获胜者 −2，要不要更重。
