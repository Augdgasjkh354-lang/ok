# 调查：繁荣度上限能不能提到原来的 10 倍（100 → 1000）

调查日期：2026-11-10（Claude）。只查了源码，没改代码。

## 结论

**技术上可以，但只改上限没有用，还会把经济搞坏。**
- 繁荣度就是一个普通的 Slot（`slot_town_prosperity`），引擎本身不读它，存档里存多大的数都行，旧存档也不受影响。
- 但原版有 20 多处公式直接拿繁荣度去乘，默认它最多是 100。上限一放开，这些地方会一起翻倍。
- 而且繁荣度会自己往「理想繁荣度」回落，理想值最高只有 65～70。上限改成 1000，城镇也涨不上去，除非另外加一股力量把它往上推。

所以真正要定的问题是：**你想让繁荣度提到 1000 带来什么效果？** 答案不同，做法完全不一样，见文末。

## 1. 上限卡在哪

| 位置 | 内容 |
| --- | --- |
| `change_center_prosperity`（`build/module_scripts.py:34365`） | 所有加减繁荣度的统一出口，`val_clamp 0..100`。改这一处，上限就放开了。 |
| 开局初始化（`build/module_scripts.py:7418`） | 理想值＋随机数，`val_clamp 0..100`。 |
| 匪帮骚扰村庄（`build/module_scripts.py:59850`，Mod 自己的） | 直接写 Slot，只减不加，不受影响。 |

## 2. 为什么改了上限也涨不上去

`get_center_ideal_prosperity`（`build/module_scripts.py:34433`）：理想值 = 65 − 缺货程度 × 2，村庄有鱼塘再 +5，**最高 70**。

每月的触发器（`build/module_simple_triggers.py:636` 附近）让繁荣度往理想值靠：低于理想值就慢慢涨，高于理想值就慢慢跌（只有 3% 的机会不管理想值随机 ±10）。所以现在原版的城镇很少超过 70，到 100 都难，更别说 1000。

## 3. 放开上限后会被连带放大的公式（原版）

| 位置 | 公式 | 繁荣 1000 时 |
| --- | --- | --- |
| 每周金库入账（`simple_triggers.py:465`） | 繁荣 × 15 + 700，城镇再 ×1.5 | 城镇每周约 23550，是现在的 8～10 倍 |
| 每周租金（`simple_triggers.py:1595`） | 基础租金 ×（20 + 繁荣）/ 120 | 城镇 2400 → 20400 |
| 商品产量和消耗（`scripts.py:14826`、`14936`） | ×（繁荣 + 75）/ 125 | 约 8.6 倍，物价会崩 |
| 商队关税（`scripts.py:15089`）、村民赶集关税（`simple_triggers.py:2159`） | 按繁荣百分比算 | 10 倍 |
| 村庄货物数（`scripts.py:22231`） | 繁荣 / 15 + 1，原注释「最多 6」 | 67 件，可能超出库存格子 |
| 城镇货物数（`scripts.py:48591`） | 25 ×（1～2 倍） | 约 475 件，超出库存格子 |
| 收税任务（`simple_triggers.py:3551`） | ×（30 + 繁荣）/ 80 | 约 13 倍 |
| 劫掠村庄所得（`game_menus.py:8709`） | 50 + 繁荣 × 5 | 5050 |

| 领主 AI 选劫掠目标（`scripts.py:43120` 等） | 按繁荣挑村子 | 只是更偏向繁荣高的，问题不大 |

## 5. 三种做法

**做法 A：只改上限（不推荐）**
改一行 `val_clamp`。实际效果几乎为零（城镇回落到 70），偶尔 3% 的随机涨幅叠上去时，上面那些公式会突然放大。

**做法 B：把刻度细 10 倍，含义不变**
上限 1000，同时把所有公式除以 10，「1000」等于原来的「100」。玩家看到的数字变大了，游戏里的实际效果不变。要改 25 处左右，换来的只是显示上的细一些，不值得。

**做法 C：让繁荣真的能长到 100 以上，越往上越难（推荐，如果你要的是「城市可以发展」）**
1. 上限放到 1000（或者先放到 300 试试）。
2. 给「理想繁荣度」加一股向上的力，而且必须是**玩家或世界真正投入了什么**才会涨：例如作坊扩建、入股、村庄投资、长期没被劫掠、商路通畅（3.0 第四批已经在记最近一次有商队成交的日子）。没有投入就照旧回落。
3. 100 以上的部分**打折生效**：例如收入、产量只按 100 + (繁荣 − 100) / 4 算，防止经济爆炸；库存件数封顶。
4. 繁荣度文字加两三档（「繁华」「冠绝卡拉迪亚」），城里人和镇长的台词跟着变。
5. 旧存档的数值都在 0～100，不受影响，不需要新 Slot。

做法 C 要动原版的每周结算和经济公式，属于 AGENTS.md 说的「改原版流程」，应该交给 GPT，或者由我写好规格再交出去。改的地方有 15～20 处。

2. 如果是做法 C：上限先定 300 还是直接 1000？哪些投入能把繁荣往上推？
