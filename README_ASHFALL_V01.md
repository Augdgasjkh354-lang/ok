# 《卡拉迪亚：烽烟与暗流》v0.1 — 战争留下的伤痕

**当前状态：源码实现、Module System 编译、静态兼容审计及重复构建通过；尚未在 Windows《战团》1.174 客户端做实机验收。**

基础版本：FewerBandits v7.5。现有宫廷政治、领主恩怨、派系、情报与人情债系统不改规则。

## 核心原则

本版**没有独立的「民心」属性**：

- 新增 **战乱度** `0..100`：反映洗劫、邻近战事、地方秩序与恢复情况。
- 直接读取原版 **玩家与村庄关系** `slot_center_player_relation`：用于好感及原版征募规则。
- 直接读取原版 **繁荣度** `slot_town_prosperity`：原有经济值。洗劫时原版的 -60 繁荣度仍由原版处理；本版不重复扣除。

不在这一版本中加入民心、难民、叛军、匪首、补给运输队或贵族政治干预。

## 玩法与数值

| 动作/事件 | 战乱度变化 | 其他效果 |
|---|---:|---|
| 村庄进入遭洗劫状态 | +8 | 每村每天只记录一次新战乱冲击 |
| 村庄被完全洗劫 | +35 | 同阵营且地图距离 < 13 的邻村各 +6；每天只记一次 |
| 村庄易主 | +12 | 每日结算时检测变更；首次读旧档不计 |
| 出资救济 | -3 | 扣 600 第纳尔；玩家与该村关系 +4，繁荣 +2 |
| 组织巡防 | -12 | 扣 200 第纳尔，队伍需至少 20 名非俘虏成员；村庄关系 +1 |
| 运粮赈灾 | -5 | 扣 2 份 `itm_grain`，村庄关系 +2，繁荣 +3 |

前三项援助只能在**战乱度至少 20**的村庄发起；同一村庄共用 **7 游戏日冷却**。敌对、正在遭洗劫或被土匪占据的村庄不可援助；已被彻底洗劫的村庄仅可出资救济。援助在当场检查条件并扣除资源，下一游戏日的地区更新完成一次性效果，避免反复点菜单刷奖励。**补充：援助完成日若符合自然恢复规则，会额外产生当日的自然战乱衰减。**

自然恢复：最近 7 天内遭洗劫不恢复；正在遭洗劫不恢复；否则交战王国村庄每天 -1，和平王国村庄每天 -2。数值限制在 0..100。玩家独立王国作为参战判定主体之一。

战乱分级：0–19 安宁、20–39 不安、40–59 动荡、60–79 危急、80–100 崩溃。

玩家可募志愿兵人数：战乱 40–69 时按原版结果的 90% 向下取整；战乱 ≥ 70 时按 75% 向下取整；其他时候不修改。原版关系门槛、募兵种类/等级及 NPC 募兵脚本完全保留。

## 游戏内入口

- 进入任意村庄 → **「查看地方战乱与援助」**：查看当前战乱、原版村庄关系、原版繁荣度、近期事件、冷却与待结算事项。直接选择资金、巡防、谷物援助；条件不足时提供中文反馈。
- 营地 → 作弊菜单 → **「烽烟与暗流测试（v0.1）」**：自动选取玩家最近的一座村庄，可模拟一次完成洗劫对战乱及邻村的影响（**不会扣原版繁荣度，也不改变原版被洗劫状态**）、清空该村战乱、手动进行今日结算。仅在测试存档中使用。

## 安装（必须已有 FewerBandits v7.5）

1. 先备份 `MountBlade Warband/Modules/TestMod/` 整个目录和存档。
2. 解压「烽烟与暗流-v0.1-增量游戏包.zip」。把其中 `FewerBandits/` **内部的六个 `.txt` 文件**直接覆盖到你现有的 v7.5 模组目录（示例：`Modules/TestMod/`）。
3. 不要把 `FewerBandits/` 整个文件夹作为新的嵌套子目录，也不要只覆盖 v7.4。
4. 使用旧存档前备份；旧版本的新增 Slot 按第一次使用进行初始化：普通村庄从战乱 0 开始，已有被洗劫村庄为 43；初始化不会重复扣原版繁荣度。
5. 在游戏内进入村庄查看新入口。最好先用**测试存档**运行 30 天，再用旧存档进行回归验收。

## 完整源码与重新编译

- 权威源码：`build/module_*.py`（v7.5 既有文件 + v0.1 修改）。
- 历史局部源码快照：`baseline/v75/source/`；历史编译数据：`baseline/v75/compiled/`。
- 在本压缩包根目录执行：`python build_v01.py`。
- 完成后，`game-data/` 包含全部 32 个编译后 `.txt` 文件。增量安装包只提供六个差异文件。
- 静态验证：`python tests/verify_v01.py`。
- `build_v01.py` **严格以已经本地化的 v7.5 生成数据为基线**，避免二次运行历史中文本地化脚本；既有对话生成文件与 v7.5 保持逐字节一致。

## 兼容性审计与限制

- 完全不重排原有 script/menu/trigger ID。只在旧版数据后追加 12 个脚本、2 个菜单、1 个 24 小时触发器、1 个全局变量、11 个村庄 Party Slot（650–660）。
- 原版 `script_village_set_state`：仅读取变更前状态，并在真实的被洗劫状态变更后钩入新代码。
- 原版 `script_update_volunteer_troops_in_village`：仅在原版已得出随机人数后做一次系数修正。`script_update_npc_volunteer_troops_in_village` 不变。
- 改动的编译数据：`menus.txt`、`scripts.txt`、`simple_triggers.txt`、`quick_strings.txt`、`variables.txt`、`variable_uses.txt`；另外 26 个与 v7.5 完全一致。
- 旧 v7.5 已存在的三个编译器「脚本可失败」提示仍存在，本版新增脚本无此类提示。
- 静态检查不能代替 Windows 客户端的旧存档测试；新增菜单、对话缓存、实际天数触发与不同战役进度仍需实机确认。
